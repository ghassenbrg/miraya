# Miraya LAN protocol v1

Transport: a single TLS 1.2+ TCP connection, receiver listens on an ephemeral port and advertises `_miraya._tcp.` using DNS-SD. TXT `v=1`, `id=<stable receiver UUID>`. No internet services. Default manual port 7421 (receiver uses this when available). TLS server identity lives in AndroidKeyStore. SHA-256 of DER leaf certificate identifies TV. TV displays first 16 hexadecimal characters grouped XXXX-XXXX-XXXX-XXXX. First-time sender must enter this code from the physical TV; TLS verifies that prefix **before** sending any application data. Following successful approval, sender pins entire certificate fingerprint. Do not advertise certificate fingerprint. TV must separately approve unknown senders with remote. Tokens are random 32-byte base64url secrets, stored privately on receiver, Keychain on Mac. Never log tokens. Known UUID alone is not authentication. Clearing trusted Macs revokes all tokens. Unknown clients rate limited and approval expires in 30s. One active sender at a time. TLS handshake/read deadlines and bounded clients required.

Every packet has a 24-byte big-endian header: magic 4 bytes ASCII MRY1; type UInt8; flags UInt8; reserved UInt16=0; payload length UInt32; presentation time UInt64 microseconds (valid range 0...Int64.max; high bit must be zero for cross-platform clock arithmetic); sequence UInt32. Maximum payload 4 MiB, control/config max 64 KiB. Reject invalid magic, flags other than bit0 on video, reserved, length, type. Sequence increments per outgoing direction, starts at 0; diagnostic only. pts is sender monotonic media timestamp, same clock for video/audio (CMSampleBuffer presentation time microseconds). Control pts=0.

Types: 1 UTF-8 JSON control object, 2 UTF-8 JSON video config, 3 H.264 Annex B access unit, 4 signed PCM16LE interleaved stereo 48000Hz. Video flags bit0=IDR. Config SPS/PPS are base64 **raw** NAL units without start codes. Config always precedes first video and each encoder recreation. Audio max 19200 bytes per packet (100ms), no microphone. Both sides ignore unknown JSON keys, reject unknown required op/version.

Handshake sender -> `{"op":"hello","version":1,"clientId":"UUID","name":"Mac name","token":"optional secret"}`.
Receiver -> `{"op":"pending"}` when waiting for TV approval; then `{"op":"welcome","version":1,"receiverId":"UUID","name":"TV name","token":"secret","maxWidth":1920,"maxHeight":1080}` or `{"op":"error","code":"denied|busy|auth|version|timeout|protocol|decoder","message":"human readable"}` followed by close. Known client with invalid token fails; never silently re-pair. New pairing only with foreground TV approval. Welcome token is sent for both known and newly approved client.

After welcome, sender sends `{"op":"start","audio":true|false}`; receiver -> `{"op":"ready"}` when surface is available and stream may begin. Video config: `{"width":1920,"height":1080,"fps":30,"sps":"base64","pps":"base64"}`. Decoder renders letterboxed, never stretches. Receiver can return `{"op":"requestKeyframe"}` after dropping decoder backlog. Sender may skip capture before encoding under pressure; must not arbitrarily drop reference frames on wire. Bounded outbound buffering must fail/reconnect rather than accumulate seconds of stale frames. Receiver drops stale output frames and input until next IDR when overloaded. Receiver sends `{"op":"stats","frames":N,"dropped":N,"lastPts":N,"audioFrames":N,"audioFramesWritten":N}` every 250ms while streaming. `lastPts` is the most recent scheduled video timestamp (-1 before any frame), `audioFrames` is the AudioTrack playback head, and counts are cumulative per session. Sender uses these optional telemetry fields for adaptive bitrate and end-to-end backpressure: pause capture when the last transmitted frame is more than 700ms ahead of acknowledged output, fail/reconnect if playback cannot progress for five seconds. Local TCP send completion alone does not prove playback progress.

Either side can send `{"op":"ping","nonce":N}` every 2s; peer replies pong same nonce. 10s without incoming data terminates session. Sender sends stop on user stop, receiver sends stopped then closes session; receiver remote Back sends stopped then closes. Unexpected disconnect ends capture; Mac may retry known TV for up to three attempts, but must clearly show reconnecting and stop when cancelled. Never resume after explicit TV stop/denial. A newly authenticated connection must send start before media.

Scope: macOS 13+, Android TV API 26+, SDR H.264 8-bit 4:2:0, maximum 1920x1080 at 30/60 fps (720p mode for weak networks), system audio optional. Receiver limits actual support with MediaCodec; unsupported stream returns useful error. No cloud, Bluetooth, remote input, DRM bypass, UPnP or port forwarding.
