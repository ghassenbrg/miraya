# Miraya 0.1.0

- Entire-display, single-window and selected-area capture; Desktop and Watching video profiles.
- Direct video/audio playback for selected local files and compatible HTTPS media URLs, including HLS/DASH. Original local media uses the authenticated encrypted connection, with bounded range reads and no extra file-server port.
- TV-native buffering, seeking, pause/resume, volume, audio-track and subtitle selection; external SRT/WebVTT files.
- Local diagnostic history (up to 72 hours / 2,000 events) and manual JSON export with allowlisted numeric measurements, excluding content, media URLs, file/device names and pairing credentials.

- Direct encrypted LAN screen sharing with H.264 video and stereo system audio.
- Six-digit comparison pairing, saved TVs and individual trust management.
- Live quality/audio/volume controls and pause/resume.
- TV display reporting, Fit/Fill/Stretch picture modes and adjustable edge margins.
- Quality choices from 480p/15 to 720p/60 and 1080p/60 maximums; automatic adaptation to receiver/network capacity.
- Immediate startup milestones with elapsed time and cancellation; live sharing confirmed by the first TV-presented frame.
- Mac-only / TV-only / Both audio routing, with temporary local-mute restoration.
- Follow TV resolution, detail-first adaptation and a separate Live Metrics window for requested/delivered quality and network/encoder diagnostics.
- Stable Mac signing support, capture-permission checks, and snapshot/production release workflows.

Screen mirroring can show protected video as black. The owner confirmed Chrome graphics acceleration off resolved Netflix capture on this Mac while preserving browser extensions; service/device behavior varies. A 4K TV display mode does not imply 4K screen-sharing encoding; Miraya currently encodes up to 1080p. Actual frame rate, resolution and latency depend on both devices and the LAN.
