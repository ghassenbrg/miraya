# Product and visual direction

Miraya uses the supplied Mac/TV visual references as a direction for its actual native applications: midnight navy surfaces (`#0B1020`), electric cyan (`#00E5FF`), blue (`#3B82F6`), soft blue (`#A7C7FF`) and near-white (`#F4F8FF`). Rounded panels, clear device selection, familiar screen/audio controls and a prominent sharing action carry across both apps. The app icon is repository-native vector artwork rendered at all macOS icon sizes.

The normal flow is **open Miraya on the TV → choose the TV by name on the Mac → share**. DNS-SD discovery populates Available TVs automatically. Each TV can have a persistent friendly room name. Name changes affect discovery presentation; they do not change its stable receiver identity or saved cryptographic trust. Receiver names are untrusted labels, so first-time pairing still compares a fresh six-digit code on both screens and requires the TV remote's approval.

The Mac groups discovered/saved TVs beside display, quality and system-audio controls. First-time pairing is a focused sheet with a large six-digit comparison code and a Codes match · Pair action, with no typing. Connection and sharing states are shown explicitly, and a stop action remains available during streaming or a retry. Quality, system audio and Miraya playback level can change while connected. Quality/audio-source changes briefly update capture and tracks within the existing authenticated native media session. Pause stops capture, resume restarts it, and TV Back still ends sharing. Settings persist; a saved-TV manager and TV-side trusted-Mac list allow individual revocation. A scrollable settings area keeps pause/stop visible at the minimum window size. Connection details exposes rendered frame rate, drops, native encoder target, estimated capacity and network round trip; network RTT is explicitly distinct from display latency. Failed discovery has useful recovery text. Manual IP/port entry is a fallback behind Connect by address, not the initial setup path.

The TV is built for viewing from a distance and operating with a D-pad. It has a readable ready screen, pairing instructions, persistent TV naming, visible remote focus and full-screen aspect-correct playback. Manual address information lives in Connection details so IP addresses do not dominate normal use. New-sender approval defaults to the safer decline action; approval requires a deliberate remote selection. Back stops a stream. Leaving the activity stops receiving and discovery; V1 does not imply background availability or wake-on-LAN.

The references contain illustrative device states, nearby-device examples and photographic surroundings. Production screens display only actual discovery/connection state, actual display choices and functional controls. Native window chrome, pickers and accessibility semantics are retained. Decorative screen-to-screen wave artwork communicates the product without replacing meaningful status or fabricating a connected receiver.

## Pairing and capture access (Mac 1.0.1)

Selecting a TV highlights it; the primary button says **Pair & Share** for a new TV and **Start Sharing** for a saved one. The card explains that next step explicitly. Screen-recording permission is checked after TV identity verification and remote authorization, before the start command or any media capture. A denied or stale Mac capture grant therefore cannot suppress the six-digit pairing UI. The verified pairing stays saved if capture permission is denied.

Failures now open an alert as well as remaining in the window. ScreenCaptureKit's user-declined error offers Screen Recording Settings and explains how to refresh an already-enabled stale grant after quitting older copies. Help includes the running app path and version so local builds can be distinguished. Permission changes remain a user action.

Version 1.0.2 adds **Check Screen Access** in the help panel. It calls ScreenCaptureKit's shareable-content API, independent of TV availability, and reports whether the app can access an available display. It does not start a capture stream or send media. A successful check confirms capture authorization, not Wi-Fi performance. This makes an enabled-but-stale macOS permission distinguishable from a reachable TV or a valid saved pairing.

## Version 0.1.0 additions

Build 6 adds a mode selector: **Share screen** or **Play video on TV**. Mirror sources include Entire display, One window (refreshable native list) and Selected area (drag an overlay; Esc cancels). The window stream stays attached to that window while other apps are used; its audio is captured at app scope. Desktop chooses 1080p/60 with motion priority; Watching video chooses 1080p/30 with detail priority. Subsequent manual quality/priority changes are respected, including across app launches.

Direct playback selects an explicit local video/audio file or compatible HTTPS media URL, plus optional SRT/WebVTT subtitles. The same secure pairing applies, without asking for screen capture. Its UI reports preparing/buffering/playing/paused/ended, original dimensions, seek position/duration and buffered-ahead time, with play/pause, stop, volume, audio-track and subtitle selection. The TV provides native playback controls. Mirror FPS and encoder settings are not shown as direct-player settings. Screen sharing remains the path for browser-extension overlays. Generic website-page links, browser blob URLs, browser login state and protected-service licenses are not silently converted into playable media.

Live Metrics includes a manual **Save diagnostic report…** action. Its privacy explanation states the retention bounds and excluded content/credentials; no automatic upload is offered. Numeric symptoms produce measured explanations and suggested actions without claiming router distance, signal strength or a uniquely diagnosed fault.

The owner has set the current app version to 0.1.0. New paired receivers publish their viewport and panel display mode. The Mac reveals **TV picture** controls while connected: Fit preserves the entire display; Fill crops to fill; Stretch changes proportions. A single symmetric edge margin compensates for overscan. A matching TV-remote Picture dialog is available while idle or sharing, and the TV saves these settings. Fill uses the renderer's crop transform, keeping Surface allocations within the TV viewport even for portrait sources.

Quality offers 480p/15, 720p/30, 720p/60, 1080p/30 and 1080p/60 ceilings. The UI explains automatic decoder/network adaptation. Native playback capability and end-to-end progress protections remain enabled.

The Netflix TV-app launcher was removed at the owner's request. The actual use case requires Chrome translation and dual-caption extensions on the Mac. A Chrome graphics-setting compatibility workaround was confirmed by the owner; Miraya does not change browser settings itself.

Build 5 adds immediate connection acknowledgement, named secure-connection/capture/media milestones, elapsed time, cancellation, and first-TV-frame confirmation before showing Sharing. Keychain writes and native media-factory construction run away from the UI actor. Follow TV resolution uses the reported viewport within the chosen quality ceiling. Picture detail is the default priority: lower frame rate before reducing pixels. Smooth motion retains resolution adaptation as an explicit alternative. Delivered dimensions/FPS stay visible, and Live Metrics opens a separate diagnostics window that distinguishes measured network issues, encoder CPU/bandwidth adaptation, receiver picture scaling and negotiated decoder limits. Router distance is not inferred.

Audio routing offers Mac only, TV only and Both. TV only clearly describes its temporary device-wide Mac mute; a local helper owns restoration on Stop/quit or sender exit. Unsupported output-device mute reports an error and returns to Both.

Creative Design is an isolated, unapproved exploration. The Luna task was interrupted at the owner's request; its proposal is not implemented. `Creative Design/FRESH-START-PROMPT.md` is the separate-session handoff.
