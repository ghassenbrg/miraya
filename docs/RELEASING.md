# Building and releasing

## Local builds

```sh
scripts/test.sh
scripts/build-macos.sh
scripts/build-android.sh debug
```

The app bundle and installable development APK are written to `dist/`. The APK uses the standard local debug keystore generated by Android tooling. Its key is suitable for development, not a public release. No signing key or password belongs in this repository.

`scripts/build-macos.sh --universal` builds arm64 and x86_64 into one app. Default builds use the host architecture. Version metadata can be set with `MIRAYA_VERSION=X.Y.Z` and `MIRAYA_BUILD_NUMBER=N`. macOS 13 is the deployment target; building with a newer SDK does not make newer APIs safe without availability checks.

## macOS Developer ID and notarization

An Apple Developer Program account and Developer ID Application identity are required for normal public distribution outside the Mac App Store. The repository intentionally includes neither credentials nor an app-store upload flow. The packaged app uses hardened runtime, no JIT or unsigned-library exceptions, and no sandbox-specific capture entitlement.

List your available identities, then build and verify:

```sh
security find-identity -v -p codesigning
CODESIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' scripts/build-macos.sh --universal
codesign --verify --strict --verbose=2 dist/Miraya.app
ditto -c -k --sequesterRsrc --keepParent dist/Miraya.app dist/Miraya-macOS.zip
```

Store notarization credentials in a local keychain profile using Apple's `notarytool store-credentials`, then submit, staple and re-archive:

```sh
xcrun notarytool submit dist/Miraya-macOS.zip --keychain-profile MirayaNotary --wait
xcrun stapler staple dist/Miraya.app
xcrun stapler validate dist/Miraya.app
spctl --assess --type execute --verbose=2 dist/Miraya.app
ditto -c -k --sequesterRsrc --keepParent dist/Miraya.app dist/Miraya-macOS.zip
```

Do not modify files inside the app after signing. Test the downloaded notarized archive on a clean Mac, including first-run network/capture permission and Keychain behavior. Ad-hoc builds do not establish a verified Developer ID identity and are not notarized. See [Apple's notarization guide](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

## Android release signing

Create a release key locally and back it up securely. Enter passwords interactively, not in source files or shell history:

```sh
keytool -genkeypair -v -keystore /secure/path/miraya-release.jks -alias miraya -keyalg RSA -keysize 3072 -validity 10000
```

The Android Gradle project accepts `MIRAYA_KEYSTORE`, `MIRAYA_KEY_ALIAS`, `MIRAYA_STORE_PASSWORD`, and `MIRAYA_KEY_PASSWORD` environment variables for release signing. Load passwords from your secret manager into the process environment, then:

```sh
export MIRAYA_KEYSTORE=/secure/path/miraya-release.jks
export MIRAYA_KEY_ALIAS=miraya
# Set MIRAYA_STORE_PASSWORD and MIRAYA_KEY_PASSWORD securely in your environment.
scripts/build-android.sh release
"$ANDROID_HOME/build-tools/36.0.0/apksigner" verify --verbose --print-certs dist/Miraya-TV.apk
adb install -r dist/Miraya-TV.apk
```

Without signing variables, the release task produces `dist/Miraya-TV-unsigned.apk`, which is not directly installable. You can align/sign it separately with SDK `zipalign` then `apksigner`; align before signing. Never treat an unsigned artifact as a finished installable release. See [Android command-line builds and signing](https://developer.android.com/build/building-cmdline).

Use the same key for every update. Keep the Gradle application version/versionCode in sync with the release tag. Test upgrade from the previous release without losing trust. Switching from debug to release signatures normally requires an uninstall; disclose that trust resets.

## Release checklist

- Run unit tests and Android lint; build Mac universal app and APK from a clean checkout.
- Complete the physical-device checks in [TESTING.md](TESTING.md), including sustained screen+audio playback and adverse networks.
- Verify release signatures and minimum-version behavior; notarize and staple the Mac app.
- Install each final artifact, not just a development build; verify TV launcher icon/banner and remote focus.
- Check licenses, documentation, version metadata and known limitations.
- Publish SHA-256 checksums and identify which artifacts are signed/notarized. Never upload keys or tokens.

`scripts/package-release.sh` runs automated checks, builds universal Mac and debug/release Android artifacts, zips the app and writes checksums. It does not submit to Apple or publish anywhere. Without credentials, its outputs include a local ad-hoc Mac build, an installable signed development APK, and an unsigned Android release. Release builds remove stale artifacts of the opposite signing mode so an old signed APK cannot be mistaken for a new release.
